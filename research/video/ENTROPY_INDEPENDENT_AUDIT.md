# Independent entropy arithmetic audit

6 November 2026. Scope: a second source-expression and system audit of the proposed VVC/AV1 use. This is not compiled-code equivalence, a normative VVC specification audit, hardware measurement, or evidence of a complete accelerator win.

The [independent checks](entropy_independent_checks.py) reconstruct the pinned native VVenC update using its actual up-move tables. They resolve every block entry through summaries **before** replaying blocks, then compare the reconstructed packed 10/14-bit lanes and the combined index used *before* each update. All 13 allowed configured rate pairs are exercised on all-zero, all-one, alternating and seeded random 128-bin traces from packed midpoint initialization. The independent script imports the existing certificate/map implementation; it does not independently prove that implementation or an indefinite capacity bound. [Results and source hashes](entropy_independent_results.json).

The algebraic VVC reduction is correct within the configured aligned-state contract. If `H=2^b-1` and `D=2^k`, the unscaled native update is `s-(s>>k)+bit*(H>>k)`. It equals `floor(((D-1)*s+D-1+bit*(2^b-D))/D)`. Preserve the pair of hypotheses; the downstream index is `((s0<<5)+(s1<<1))>>8`. The checks cover that index, not fraction-bit table contents or accumulated candidate costs. Primary sources: pinned [Contexts.h](https://github.com/fraunhoferhhi/vvenc/blob/6441f64f9997e9ab8a12d4ac600998a104aa5ddf/source/Lib/CommonLib/Contexts.h) and [Contexts.cpp](https://github.com/fraunhoferhhi/vvenc/blob/6441f64f9997e9ab8a12d4ac600998a104aa5ddf/source/Lib/CommonLib/Contexts.cpp), independently retrieved through the GitHub connector.

The constructor sets `m_rate=DWS=8`, which gives `rate0=0` and a zero-gain first hypothesis. That case falls outside `Rule`'s `0<A<D` requirement. Ordinary `CtxStore::init` does call `setLog2WindowSize` for each context, establishing the tested configured rates. Scope claims must therefore say *initialized configured contexts*. Directly updated constructor objects, changed windows, resets and snapshot restores need their specified handling. The check does not validate every encoder call path.

An especially strong inexpensive exact baseline follows from the same algebra. Let `G(s)=s-(s>>k)`. The zero-bin update is `G(s)` and the one-bin update is `H-G(H-s)=s+((H-s)>>k)`. Since `H-s` is the `b`-bit complement, conditional complements around one shift/subtract core implement both branches exactly. This identity is exhaustively checked over all scalar states at the tested rates. It is a hardware design candidate, not a routed timing/area result. A general multiply-based serial baseline would be misleading for this workload.

For AV1, the second test complements the forward-CDF update and compares all values in the **closed** interval `[0,32768]` at rates 4–7 to the proposed inverse-CDF floor formulas. These agree. “15-bit probability” refers to the scale; the inclusive endpoint needs 16 unsigned storage bits. `Rule(bits=15)` only admits `[0,32767]` and cannot directly represent this full domain. The low-level map primitive may operate on supplied domains including 32768; a variable-rate/offset certificate and full valid-CDF-vector test remain separate obligations. The consulted HTML explicitly identifies itself as a working document and links the approved PDF; avoid calling the HTML itself the approved specification. [AOMedia symbol decoding process](https://aomediacodec.github.io/av1-spec/#symbol-decoding-process).

The original main audit's local-map comparisons were meaningful, but its first replay loop advanced block entries natively and then compared block-split native execution against native serial execution. That did not independently exercise map-derived entry resolution. This independent test exercises that path. The parent subsequently corrected its main script to resolve all boundaries through maps before replay and reran it successfully; the saved main results identify that corrected script by hash.

The system-level gap remains decisive. A decoder does not know future decoded bins/context choices before arithmetic decoding supplies them. An encoder with fixed known candidate bins may precompute probability trajectories, but arithmetic range state, renormalization and output behavior remain dependencies. Rate estimation also consumes *pre-update combined states* and lookup costs for every bin, so final-state summaries alone do not produce an exact accumulated rate; replay or a separately justified cost summary is required.

RDO is a potentially easier consumer, not an automatic exactness mandate: an encoder may use approximate rate estimates and still emit a valid bitstream. Exact estimator reproduction matters when preserving a chosen encoder's decisions/output is the stated contract. Measure the actual RDO paths; some stages can use frozen probability costs, while candidate/snapshot parallelism, ordinary shifts/adds, context caching and limited exact unrolling are strong inexpensive alternatives. Future candidate bins may themselves depend on earlier rate-driven decisions. Until a concrete stage supplies its known input schedule and a profile shows probability evolution dominates, this remains an arithmetic fit with an unproved application/performance fit.
