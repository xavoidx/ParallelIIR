# Narrow streams and infrequent outputs: adversarial application review

6 November 2026. Scope: PDM/sigma-delta streams, pulse counting, radiation-detector processing and emulation, binary monitors, and decimated DC/power/EWMA statistics on small FPGAs. Read together with [THIRD_PASS_VERDICT.md](../direction/THIRD_PASS_VERDICT.md) and [FEASIBILITY_RED_TEAM.md](../direction/FEASIBILITY_RED_TEAM.md). This is application research, not measured RTL performance.

## Verdict

**Narrow input and endpoint-only output repair two architectural weaknesses, but the inspected applications do not yet establish a winning workload.** Bit packing can remove the earlier 17–32-bit input-bank problem, and an endpoint map can avoid replay when only block boundaries are consumed. Neither establishes that the original fractional rounded recurrence is the limiting operation.

Actual small-FPGA examples are valuable counterexamples: a wearable iCE40 bitstream lock-in uses pruned CIC filters; a small Spartan-6 nuclear pulser already generates complete waveforms at 40 MHz; PDM products put CIC/FIR decimation before a fractional IIR. The closest implementation lead is a configurable FPGA EWMA with documented finite widths, alongside an implementation explicitly using clustered lookahead to relieve a first-order feedback clock limit. Those sources still omit the original per-update rounding contract and a measured small-device service deficit.

The best **new-design experiment**, rather than a sourced existing bottleneck, is a cold packed binary or few-bit trace, a fixed short-memory quantized EWMA, and exact outputs only at agreed block boundaries. It must beat specialized two/four-step unrolling, binary-alphabet tables, exact repeated-symbol skipping, endpoint coalescence, and shared-base ranks. A useful monitoring consumer and its required horizon remain missing.

## The high-rate/short-memory trap

For a new endpoint monitor, explicitly choose the physical or event horizon before choosing a convenient mask. For input rate r and desired half-life T, the required retention is approximately `a=2^(-1/(r*T))`. The ideal uncertainty scale is approximately `1/(1-a) ≈ r*T/ln(2)` state units. Increasing fractional state precision does not itself fix this horizon problem.

Derived illustrations, not observed configurations:

| Original retention / requirement | Event half-life | Physical half-life or scale |
|---|---:|---:|
| 63/64 at 3.072 Mbit/s | 44.0 bits | 14.3 µs |
| 63/64 at 20 Mbit/s | 44.0 bits | 2.20 µs |
| 63/64 at 250 Mbit/s | 44.0 bits | 176 ns |
| 63/64 at 1.25 Gbit/s | 44.0 bits | 35.2 ns |
| 1 ms half-life at 20 Mbit/s | 20,000 bits | ideal scale about 28,854 |
| 1 ms half-life at 1.25 Gbit/s | 1,250,000 bits | ideal scale about 1.80 million |

A tiny certificate therefore tends to describe a very fast transient statistic on a high-rate bitstream. Reading one endpoint every millisecond can miss the transient that made such a short horizon useful. If the real requirement is “raise an alarm whenever the filtered value crosses a threshold,” endpoint sampling is a different specification; every-event threshold equivalence or a certified interval maximum is needed. Endpoint state maps alone do not provide it.

Long-memory lowpass reconstruction also has alias/stopband requirements. Substituting a short-pole EWMA for sinc3/CIC/FIR simply to shrink certificates changes the filter. Conversely, replacing a chosen long pole by a shorter one is not an acceleration of the original filter. For a new design, filter fidelity and a consumer-approved observation schedule must justify the choice before implementation.

## Where exactness is defensible

The strongest rationale is replacing an established quantized reference used for firmware equivalence, trace replay, deterministic test generation or decisions near a fixed threshold. It is acceptable to introduce a new golden integer monitor, but document why a deterministic integer API is useful, and measure whether ordinary approximate filtering already meets the consumer's requirement. Analog noise and an exponential physical model do not by themselves require reproducing every intermediate quantization.

The original arithmetic must be recovered. Even two cheap “same-pole” shift filters can differ. With unsigned y=1, x=0 and k=6, `floor((63*y+x)/64)` produces zero, while `y-(y>>6)+(x>>6)` produces one. The latter's independently truncated terms cannot silently be replaced by a fused floor recurrence. A retained high-precision accumulator with only its output truncated is another distinct state machine. Recover reset, signed floor/toward-zero behavior, saturation, carries, gating, coefficient encoding and **every** narrowing point before calling an implementation compatible.

The [Sci-Compiler first-order tunable IIR documentation](https://docs.sci-compiler.com/docs/blocks/dsp/tunable-i/) explicitly identifies output-feedback clock rate as a limitation and implements factor-three clustered lookahead with Q2.30 coefficients, 16-bit unsigned/17-bit signed I/O and six-cycle latency. This is direct implementation motivation, but real-arithmetic transformed-filter equivalence is not proof of identity to an original rounded serial recurrence. Obtain both implementations and their exact state definitions. No small-FPGA area/timing result or original-rounding comparison was found in that documentation.

## Strong exact competitors specific to narrow streams

1. **Packed exact unrolling.** A binary sample supplies a select between two constant input contributions; a fixed dyadic coefficient can be shift/add/subtract wiring. Give the direct design the same packing, fixed coefficient and endpoint output schedule. Measure two/four-step unrolling at its own routed clock. A multiplier-based serial strawman is especially weak here.
2. **Alphabet-specialized block tables.** Binary or few-bit inputs offer reusable transitions. Compare short-pattern lookup, state partitioning, carry-aware unrolling and table composition before assuming the general map constructor is necessary. A full table over a wide state is expensive; that observation does not rule out partial tables or small-state monitors.
3. **Exact repeated-symbol skipping.** Pulse/error streams often contain long zero runs. For fixed forcing C, a direct engine can detect a fixed point `T_C(y)=y` and clock-gate the rest of the run exactly. Binary-lifting tables or verified quotient-band/run maps may advance other runs. Compare their memory/latency. Do not use `round(a^r*y+...)` as a shortcut: it generally loses intermediate rounding. A no-event step is not automatically a no-op.
4. **Count first, filter later, when allowed by the specification.** Window counting/popcount is an exact parallel reduction and may be the original required statistic. It does not reproduce a chronological per-bit rounded EWMA: even equal-popcount patterns can have different endpoint states. Treat it as a stronger application-level alternative only when the user needs the statistic rather than the chosen EWMA trajectory.
5. **Endpoint coalescence and ranks.** Build exact lower/upper trajectories and detect equal exits; construct a map only where ambiguity remains. Compare shared-base relative ranks on the identical certified intervals. Narrow input reduces tape storage, not the predictor or rank/select feedback cost.
6. **Natural independent work.** Microphones, lock-in tones, channels and monitor horizons are independent states. Let the direct engine interleave them to hide feedback latency. The limiting rate must be for the same state, not summed across channels.
7. **Checkpoints and cached outputs.** Repeating identical seeded pulse-generation or stored-trace tests permits cached waveforms/checkpoints. Charge cold-generation cost and amortization explicitly. A new coefficient/seed/format can justify a cold run; frequent testing does not automatically invalidate caching.

## Inputs, observations and the small-device schedule

Buffered ADC/PDM samples and a precomputed error bitmap are available independently of the EWMA result. A fixed-threshold raw-input trigger can likewise provide a known gating tape. Baseline-relative trigger gating, adaptive coefficients derived from this filter, output-driven pulse suppression, closed-loop ADC stimulation and control actions cannot be assumed known across a speculative block. Such loops require a separate causality/latency argument; do not import the open-loop proof.

For P block workers and L one-bit samples per block, the raw tape has PL bits rather than PL full-width words. Packing helps capacity, but P simultaneous independently addressed bit reads still require a bank/broadcast schedule; a 16-bit RAM word is not sixteen arbitrary-address ports. The global predictor, wide offsets, boundaries, P bases and map logic remain. No claim that the complete P=16 engine fits UP5K follows from a one-bit input.

If outputs are **only** final states of each group, replay can be removed and output order/storage are simpler. The serial baseline also emits only those endpoints. If an endpoint is needed every L samples, align map boundaries to those observations, charge partial groups and enforce the allowed added delay. Every-output waveform/filter consumers still require reconstruction. A pulse-triggered consumer may require the baseline at arbitrary trigger positions inside a block, so group-final state alone is insufficient.

One-bit high-speed interface feasibility needs an actual receiver/packing design. The [Lattice LP/HX datasheet, table 4.22](https://www.latticesemi.com/-/media/LatticeSemi/Documents/DataSheets/iCE/FPGA-DS-02029-4-1-iCE40-LP-HX-Family-Data-Sheet.ashx?document_id=49312) lists 400 MHz LVDS input buffer register-to-register performance, measured with a toggling pattern and limited to Bank 3. It is not a demonstrated 400 MHz fabric recurrence, arbitrary oversampling receiver, or UP5K guarantee. Similarly, an ECP5 SERDES family maximum establishes an available class of input interface, not an implemented EWMA requirement. Prefer a stated actual interface over an invented aggregate bandwidth budget.

## Proposed next evidence, in priority order

1. Obtain generated source for the documented IIR Average and a real deployment's rate, alpha, update rounding and observation schedule. Establish whether its service limit actually misses the same-state input deadline on a small target.
2. For a deliberately new narrow-stream monitor, interview/specify the consumer: what short transient is useful, what time horizon is required, and are block-boundary observations enough? Freeze a fixed coefficient and original integer state contract without altering them to rescue mask width.
3. Implement only a small equal-interface comparison: exact serial/two/four-unroll, exact zero-run specialization, endpoint coalescence, ranks and mask. Include predictor/certificate and collection latency. Endpoint-only avoids replay but does not waive the other stages.
4. Prefer a negative result to renaming a CIC, FIR, counter, input-delay deconvolver or already adequate low-rate IIR as a hard fractional recurrence. Presently none of the inspected narrow-stream applications clears all three gates: a real per-state rate deficit, justified exact intermediate quantization, and advantage over the strongest complete exact alternative.
